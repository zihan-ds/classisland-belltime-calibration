# 铃声自动校时（BellTime Calibration）

监听校园广播铃声、自动把 [ClassIsland](https://github.com/ClassIsland/ClassIsland) 的
**应用设置 → 时钟 → 时间偏移**校准到学校广播铃钟的 2.x 插件。

> **目标**：铃响时刻 ClassIsland 的时间误差尽量小。**不改课表**、**不改内核**（原版内核即可用）。

| 项 | 值 |
|---|---|
| 插件 ID | `belltime.calibration` |
| 版本 | **1.1.0** |
| apiVersion | 2.0.0.0（ClassIsland 2.x） |
| 平台 | Windows（miniaudio/WASAPI，需要可用的默认输入设备） |
| 本版本更新 | **[更新说明-v1.1.0.md](更新说明-v1.1.0.md)**（全部功能更新、设置项、验证方式） |

---

## 它解决什么问题

学校铃声不一定和电脑时钟对齐，而 ClassIsland 依据本机时间切换上下课。
本插件在每个课表边界附近短暂开麦，**听取真实校铃的起响时刻**，据此推算 ClassIsland 应有的时间偏移，
让课表切换与实际铃声对齐——校准语义为「跟随学校广播铃钟」。

安全默认：装好后默认处于**学习模式**，只记录识别结果、不写任何设置。观察几天、核对日志中误差合理后再手动开启自动应用。

## 工作原理

```
课表边界前 15s 布防（v1.1.0 自适应：clamp(max(配置值, |当前偏移|+10s), 配置值, 60s)）→ 开麦捕获（仅内存）
   ↓
模板锚点（v1.1.0：每个有音频的窗口先跑，命中则把下面两个闸门窗口收窄到「模板位置 ±3s」）
   命中率实测 37%：命中时 20/28 与老行为一致、8 个被改（其中 7 个改动 >6s，都是老行为抓错瞬态的窗口）
   模板对齐点落在铃段内部（比可听第一击晚 0.7~1.6s），故只当锚点、不直接当起声
   ↓（无锚点则按老行为）
起响沿闸门：窗口中心 ±8s 内找「起响后 0.5s 峰值 RMS ÷ 起响前 0.3s 基线 RMS」最大处，再回溯到这段长铃的起点、归位到起声那一刻   ← 主判据
   （半窗 2026-10-12 由 2s 加宽到 8s：必须宽于插件的偏移误差，理由见下文「两条判据为什么长这样」）
   （比值不够、但**绝对声压够高且抬升 ≥6 dB** 的候选也收：环境一吵真铃的起响比值会明显下降）  ← v1.0.5
   ↓
双窗口复核：同一判据再扫一遍「标称边界 ±8s」（与当前偏移无关）
   两侧一致 → 用开关窗口
   只有课表窗口命中 → 不写偏移，落一条**旁证样本**（默认不参与）                    ← v1.0.5
   两侧分歧但峰值差 ≤2 dB → 判为同一段多击钟声的先后两击，取更早的开关窗口            ← v1.0.5
   一侧强出 >6 dB → 用那一侧的坐标（课表更强时也用它：它的中心与偏移无关）            ← v1.0.5
   两侧分歧且差距在 2~6 dB 中间带 → match-conflict：不写偏移，落旁证样本，弹提醒交人工
   ↓（两个闸门都未命中时）
模板兜底测量：NCC + 音色阈值 + 攻击沿校验（搜索半窗 v1.1.0 起 = max(配置值, |当前偏移|+8s)）   ← 辅助判据
   ↓（两者都未命中）
记 no-trusted-match，本次不校准
   ↓
e = t_ring − t_switch（铃响墙钟 − 实际切换墙钟）
   ↓
偏移估计 = 近期样本中位数（6h 窗；趋势外推仅在门槛满足时启用；离群 >2s 只标记不收列、**不清空样本段**）
   ↓
死区门控 → 差值在单次写入上限（±3s）内直接写入 Settings.TimeOffsetSeconds，
           超出则**只写 ±3s 分步逼近**并弹人工复核提醒                          ← v1.1.0
```

### 两条判据为什么长这样

1. **起响沿闸门（主判据）**
   精确波形模板在本场景**不可靠**：同一段铃声在不同边界录到的波形互相关很低，
   拿实录段当模板往往只命中它自己那次录音。但「铃声是突然起响」这一物理事实很稳定——
   真铃的起响比值明显高于环境声，而连续噪声里的伪匹配比值很低。
   同时，边界附近常不止一次起响（提示音、提前播放的铃声段等往往更强），
   时间门把更远处那些一并排除；而半窗取 **8 s**（2026-10-12 由 2 s 加宽）——
   它必须**宽于插件的偏移误差**，否则偏移一偏，真铃就落在窗外看不见，闸门只能抓窗内
   −40 dB 量级的房间噪声（2026-10-12 三个窗口实测选中点 −46.1 / −39.6 / −23.6 dBFS，
   而同一段录音里的真铃是 −14.8 / −12.4 / −12.9 dBFS），算出来的「所需偏移」还像一次
   正常的小修正，偏移因此越漂越远。8 s 覆盖「单次写入上限 ±3 s」+ 实测钟声落点
   （本校第一击在标称边界 +1.0~+2.5 s）+ 余量；当天 17 个窗口离线复算：加宽后 15 个有声窗口
   里 14 个两窗一致，更远处那次「提前 6~15 s 的强起响」改由强候选组与响度门槛拦。
   **环境噪声会压低比值（v1.0.5）**：起响比值是「峰值 ÷ 起响前 0.3 s 基线」，基线被环境
   噪声抬高后，真铃的起响比值会明显下降。
   因此合格候选增加一个**或条件**：峰值 ≥ −20 dBFS（真铃量级）**且**相对基线抬升 ≥ 6 dB。
   只增不减，且不触碰「起响前 0.3 s 落在数字静默里」的排除（那条按基线 RMS < −80 dBFS 直接剔除，
   防止把「麦克风恢复出声的那一瞬间」当成铃声）。
   **长铃起点回溯 + 攻击沿归位（v1.0.5）**：多击长音里闸门选中的未必是第一击 ——
   不回溯就会把坐标定在钟声中段，测得的所需偏移偏 1~4 s。
   所以选中那一击后再**向前回溯到这段持续声音的起点**：逐 10 ms 取「后 0.5 s 峰值 RMS」，
   低于「选中击峰值 − 12 dB」算落到段外，但必须**连续**低于门限 1.2 s 才算真的出段
   （否则按钟声的击间间隙处理，继续向前）；最多回溯 8.0 s，走到上限（持续噪声这类长声音）
   则保持选中击不动。两种情况都写进命中说明。
   **回溯之后再向后归位到起声那一刻**：判据与回溯用的都是向前 0.5 s 峰窗，只要那一下落在窗里就算
   「还在段内」，所以回溯出来的坐标会停在**起声之前的静音**里（2026-10-12 21:30 实测早了 0.39 s，
   这个提前量会被「所需偏移 = 课表边界 − 铃响」原样吃进偏移）。归位改用 50 ms 短窗
   （`AttackWindowSeconds=0.05`）+ 同一个门限，走到第一个真的进声的位置为止。
   **双窗口复核**：闸门窗口的中心是「内核真正切换的位置」，而它本身正是要被校准的量 ——
   半窗窄于偏移误差时，闸门就只能看见开关附近的杂音，且结果看起来像一次正常的小修正
   （2026-10-12 起半窗 8 s，这种情形已基本消失；复核仍保留：课表窗口的中心与当前偏移无关，
   是偏移长期跑偏时唯一还能看见真铃的锚点）。
   因此每窗口再扫一遍**以标称边界为中心**的同一判据窗口：两侧一致 → 照旧；**两侧分歧但峰值只差 ≤2 dB
   → 判为同一段多击钟声的先后两击**（钟声较长、两侧很容易各抓到不同的一击；
   v1.0.5），取更早的开关窗口；一侧**强出 >6 dB** 时改用那一侧 —— 开关窗口更强说明铃确实远离课表边界，
   课表窗口更强（v1.0.5 补：**支配判据对称**）说明开关窗口已被偏移锚到杂音上、而课表窗口的中心与偏移无关，
   这两种情况都不该丢掉这次测量；只有差距落在 2~6 dB 中间带（真伪说不清）才判冲突
   （`match-conflict`）——**不写入偏移**、落一条默认不参与的旁证样本、弹提醒

2. **模板匹配（v1.1.0 起改为「锚点」，仍是辅助）**
   在录音条件好时能给出毫秒级位置，但跨边界不稳定（实测 75 个窗口命中 28 个 = 37%），
   且模板对齐点落在**铃段内部**（比可听第一击晚 0.7~1.6 s）——所以它不直接当起声，只回答
   「**窗外这一段波形就是我们的铃**」：命中就把闸门的搜索区间收窄到「锚 ±3 s」，
   起声仍由「回溯 + 归位」定位；未命中则完全按老行为。
   为什么值得加：闸门的比值竞赛会被窗内瞬态抢走（2026-10-14 09:40 选中 100×、10:10 选中 188×，
   都在人声/桌椅里），而那一天 08:10 的窗口正是锚点救回来的（老行为 +2.06 s → 错约 7 s；
   锚定为 −5.00 s → 与包络真值只差 0.4 s）。命中率有限是有意接受的上限：锚点只做加分，
   不做唯一判据，所以命中率低不会让主判据退步（75 窗口全量回放：命中时 20 个与老行为一致、
   8 个被改，其中 7 个改动 >6 s）。


### 防御性设计

| 机制 | 要防的问题 |
|---|---|
| 静音窗口守卫（绝对电平下限） | 麦克风整窗未进音时，「噪声除噪声」也能凑出很高的假起响比值 |
| 整窗静默在入口作废（`silent-window`） | 整窗静默的窗口若被判为「检测到」，会污染统计与拟合 |
| 单次写入限幅 + 分步逼近（v1.1.0；旧版为「大误差拒写」） | 防止校铃钟被人工大规模校准/时钟跳变时静默改掉几秒；分步既不会一次把偏移改飞，也不需要人工盯着——**所需偏移可能超过 20 s，靠接连几个边界走完** |
| 中位数估计替代趋势外推 | 从单次测量的抖动里估斜率并外推，会让偏移在相邻边界之间来回震荡 |
| 放学校铃布防回退 | 当天最后一节之后内核 `OnBreakingTimeLeftTime` 恒为 0，导致放学边界从不布防 |
| 样本重复灌入（v1.0.5） | 手动拟合后重新装入当天样本时是**追加**而不是替换，早期样本被计两次，40 条上限更早挤掉真样本 |
| 越界事件补发（v1.0.5） | 宿主状态切换事件与主计时器 tick 抢跑时，旧代码先把 armed 清掉 → `BoundaryReached` 永不触发，窗口一直跑到硬超时（结构化历史里连越界时刻都没有） |
| 旁证样本（v1.0.5） | 只课表命中 / 双窗口冲突的窗口原先连一条样本都不落，使用者只看到「人工校准之后样本全废」；现在落一条默认不参与的旁证样本，供人工复核后再决定是否纳入拟合 |

### 单次写入上限与人工复核提醒（v1.1.0 起为分步写入）

一次要写入的时间偏移与当前偏移相差超过**单次写入上限**（设置项，默认 ±3 s）时，插件**只写 ±上限这一步**
（`reason=stepped`，分步逼近），并在 ClassIsland 界面上弹出提醒，写明边界时刻、当前偏移、本次测得的所需偏移、
本次实际写入值与差值，以及「还需几个边界走完」。

- 提醒只在**真的分步**时出现；**没有时间冷却**——同一个大差值每次都提醒（不想被打扰直接用下面的开关）；
- 由设置项**「人工审核提醒」**（默认开）控制：关掉后**「分步写入」与「双窗口冲突不写」都仍然照旧发生**，只是都不再弹提醒、只记日志。
  限幅是数据安全底线，提醒只是可选的打扰，所以两者分开；
- 提醒出现在 ClassIsland 的提醒通道里，可在**设置 → 提醒 → 铃声校时复核**单独关闭，或在同一页的**高级设置**里给它单独配提醒音/强调特效/置顶；
- **「设置 → 提醒 → 铃声校时复核 → 基本设置」里有一份同样的设置面板**（人工审核提醒开关 + 发送测试提醒），与插件设置页里那两个是同一份配置，改哪边都一样；
- 想随时确认提醒能正常弹出，用**「发送测试提醒」**按钮（该测试不受开关约束）；
- 上限可在插件设置页调整（1~120 s），改完即生效、无需重启。**不接受把它设成极大值来关掉保护**——它不是「关掉保护」的开关，
  真要减少打扰请关「人工审核提醒」。

> 为什么提醒不能只写日志：**被静默拦下的偏差，用户根本不知道要去看日志**。大差值恰恰是最需要人介入的情形
> （校铃钟被人工校过、系统时钟跳变、信号源切换），所以这条路径必须有出口。
> 而为什么不再整笔拒写：用户实测「所需偏移可能超过 20 s」（2026-10-15 更正），拒写会让这种情形永远修不回来；
> 一次 3 s 的分步则每个边界都在朝正确值走，且任何一步都不会把偏移改飞。

### 手动拟合（设置页按钮）

设置页有一张**「手动拟合」**卡片：按下「手动拟合并应用」后，插件读当天已落盘的样本、**只保留勾选「参与拟合」的样本**，
用与运行时**完全相同**的估计器
（近 6 小时中位数；趋势外推仅在样本数/跨度/残差三项门槛同时满足时启用）重算一次，并**立即把结果写入
「应用设置 → 时钟 → 时间偏移」**——**无视总开关、学习模式与自动应用开关**（这是一次显式的手动动作，按下即写）。

- **默认勾选规则**：判据写入过的 → 参与；**落在死区带内没写入的 → 也参与**；**分步写入（`stepped`）的 → 也参与**
  （同一次干净测量，只是没一次走完）；离群拒写（`outlier`）的 → 默认不参与；
  **旁证样本（仅课表窗口命中 / 双窗口冲突）→ 默认不参与**。人工在「样本管理」里的勾选始终优先。
- **「判据位置」列显示当时真实的原因**（v1.0.5）：判据在落盘时把原因一并写进样本行（`Reason`）——
  写入过 / 死区带内（未写）/ 步进写入 / 离群拒写 / 仅课表命中（旁证）/ 双窗口冲突（旁证）。
  旧样本没有这个字段，仍按「|所需偏移 − 当时偏移| ≤ 死区」反推，并明说「旧数据，原因未记」——
  上一版用这条几何反推，会把「预测落在死区所以没写」误标成「大误差拒写」（v1.0.5 的 `large-error`
  在 v1.1.0 已改为分步写入，旧样本仍按「人工复核过再说」默认不勾）。
- **为什么死区带内的样本也算干净**：死区带内意味着 |所需偏移 − 当时偏移| ≤ 死区，是**当时已经够准所以
  没动偏移**——测量本身与写入过的完全同类，偏移没动不代表这次测得不准。而离群样本（`outlier`，与稳健拟合
  差 >2 s）的差值与死区不在一个量级，两类区分度极大，判定不依赖阈值精度（阈值取设置页的「应用死区」）。
- **为什么离群拒写的默认不参与**：它的坐标连稳健拟合都对不上（多为窗外瞬态被人声/桌椅抢走），
  可信度打折。用它们拟合等于把脏值写进设置项。这里不另造判据，只用样本自带的标记。
- 写入后插件会把当天样本重新装进运行时估计器，避免下一个边界用旧序列把手动结果顶回去；
- 结果文字写在按钮旁边（写入前后的值、有效样本数、中位数、散度、趋势是否启用），日志同样留痕。

## 目录结构

```
plugin/                       插件源码（.NET 8）
├─ Plugin.cs                  入口：日志/配置/模板加载、设置页注册
├─ manifest.yml               id=belltime.calibration
├─ Models/                    设置项
├─ Services/
│  ├─ CalibrationScheduler.cs 布防：边界前 N 秒入窗（含放学校铃回退）；提前量随当前偏移自适应（v1.1.0，配置值当下限）
│  ├─ MicCaptureService.cs    窗口捕获（SoundFlow/miniaudio，48k 单声道）
│  ├─ CaptureAudio.cs         内存音频缓冲 + 采样↔墙钟映射
│  ├─ OnsetGate.cs            起响沿闸门（主判据）；可传模板锚点把搜索区间收窄为 锚 ±3 s（v1.1.0）
│  ├─ RingDetector.cs         突发起响点检测
│  ├─ TemplateMatcher.cs      模板匹配（粗定位→精定位→音色→攻击沿）；v1.1.0 起每窗先跑、命中即当锚点
│  ├─ DriftFitter.cs          偏移估计器：6h 稳健中位数 + 趋势外推；离群 >2 s 只标记不收列、不清空样本段（v1.1.0）
│  ├─ OffsetSampleStore.cs    偏移样本按天落盘（重启按最近 12h 窗口恢复序列，供离线分析；v1.0.5 起记「判据位置」与旁证样本）
│  ├─ BellReviewDecision.cs   单次写入限幅/分步判据 + 提醒开关判定（纯函数，可离线断言）
```

## 提供你自己的铃声样本（必做）

插件的**主判据「起响沿闸门」不依赖样本**，装好即可工作；样本只用于辅助的模板匹配路径
（在个别窗口能把起响点精确到毫秒级）。所以样本是**可选增强**，但强烈建议提供。

### 录制要求

- 用**本机（装 ClassIsland 的那台电脑）的麦克风**录，位置与日常使用一致；
- 在**正在响铃时**录一段，长度几秒到几十秒都行；开头多录 5~10 秒环境声更好（便于自动截取）；
- 保存为 **WAV**（插件自带 WAV 解析器；`.m4a`/`.mp3` 请先用 ffmpeg 转成 WAV）；
- 上课铃、下课铃**各录一段**（上下课铃音色差别很大，别混用同一段）。

### 导入方式（两种，任选）

**A. 设置页导入（推荐）**
1. 打开 ClassIsland「设置 → 插件 → 铃声自动校时 → 模板匹配（铃声样本）」；
2. 在「上课铃样本」/「下课铃样本」行点 **「浏览…」**，选中你录的 WAV；
3. 若你知道铃声响在录音的第几秒，在下面的「截取区间」填 `起始秒-结束秒`（如 `12.0-14.5`）；
   留空则由插件自动取「最响且持续 ≥1.5 s」的段；
4. 选完立即生效（设置页会主动重载模板库，无需重启），日志会打印 `已选择铃声样本：… 模板库已重载（已加载 N 个模板）`。

**B. 直接放文件**
把你截好的 2.5 s 模板放到插件配置目录的 `Templates/` 下，命名含「上课」/「下课」即可
（如 `上课铃.wav`、`下课铃.wav`），重启 ClassIsland。随包的两个同名文件是**静音占位**，
插件会识别并跳过它们（日志：`跳过 上课铃.wav：全零静音（随包占位文件…）`），直接覆盖即可。

### 验证样本是否可用

```powershell
# 用生产的匹配器在录音上自测（同源应接近 1.000）
TemplateTool selftest plugin/Templates/上课铃.wav 你的录音.wav 0.6 0.45 15
```

`tools/README.md` 里有完整的工具用法与标定建议。

## 配置与调参

设置项见 `plugin/README.md`。关键几项：

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用铃声自动校时 | 开 | 总开关：关掉后不监听、也不自动应用。设置页的「手动拟合并应用」按钮不受它约束（显式手动动作） |
| 学习模式 | 开 | 只记录不写；确认稳定后关闭 |
| 自动应用校准偏移 | 关 | 关闭学习模式后才生效 |
| 单次写入上限 | 3 秒 | 一次要改的偏移超过此值时**只写 ±此值**（分步逼近，`reason=stepped`）；同时决定是否弹人工复核提醒。改完即生效 |
| 人工审核提醒 | 开 | 关掉后「分步写入」与「双窗口冲突不写」都仍然照旧发生，只是都不再弹提醒（只记日志） |
| 布防提前秒数 / 铃响搜索半窗 | 15 / 12 秒 | v1.1.0 起两者都是**下限**：实际 `clamp(max(配置值, \|当前偏移\|+10s), 配置值, 60s)` 与 `max(配置值, \|当前偏移\|+8s)` —— 偏移超过 20 s 时铃才落得进窗口/搜索区间 |
| 样本管理（设置页卡片） | — | 逐条复核当天样本是否有效；作废的样本不再参与手动拟合（不影响自动应用链路）；「判据位置」列显示**当时真实的原因**（v1.0.5 起，v1.1.0 增 `outlier`/`stepped`），旁证与离群样本默认不勾 |
| 起响沿闸门参数 | 内建常量 | `OnsetGate.GateSeconds=8.0`（2026-10-12 由 2.0 加宽：半窗必须宽于插件的偏移误差，否则真铃落在窗外、只能抓到房间噪声）、`RatioMin=4.0`、`DominanceDb=6.0`（支配门：一侧强出 >6 dB 就用那一侧的坐标，v1.0.5 补对称）、`AgreeSeconds=1.0`（双窗口一致性容差）、`SameStrengthDb=2.0`（两窗口峰值差 ≤2 dB 判为同一段长铃的先后两击；差距落在 2~6 dB 中间带才判冲突，v1.0.5）、`LoudPeakDb=−20`、`MinRiseDb=6.0`（「高声压起响」或条件，v1.0.5）、`SegmentLookbackSeconds=8.0`、`SegmentDropDb=12.0`、`SegmentHoldSeconds=1.2`（长铃起点回溯，v1.0.5）、`AttackWindowSeconds=0.05`（起声归位：回溯后的坐标再走到真的进声那一刻，v1.0.5）、`AbsoluteMinRms≈−50 dBFS` |

日志：

- `<插件配置目录>/Logs/belltimecalibration-<日期>.log`（人类可读）
- `<插件配置目录>/Logs/calibration-history.jsonl`（结构化，每窗口一行，含结局、起响点、误差、门控结果）
- `<插件配置目录>/Logs/offset-samples.jsonl`（**偏移样本序列**，见下）
- `DebugDumpAudio=true` 时窗口音频转存到 `<插件配置目录>/Dumps/`（**默认关闭**，音频平时只在内存）；设置页同一张卡片里的「清除无用录音」用来收拾越攒越多的调试录音，但它只删**确实无用**的那些：**7 天以内的一律保留**（排障还要看），离线断言（`ReplayTool gate-reconcile-test`）点名用到的录音**永久保留**，文件名认不出时刻的也保留；只删 `Dumps/` 下一层的 `*.wav`，模板与样本记录不受影响

### 偏移样本序列（`offset-samples.jsonl`）

每个拿到**可信测量**的监听窗口追加一行，记录参与偏移估计的样本：

```json
{"Ts":"2026-09-15 08:10:21.683","RequiredSec":-1.6850,"CurrentSec":-1.3440,"Kind":"上课","B":"08:10:00.001","Applied":true,"Reason":"applied"}
```

| 字段 | 含义 |
|---|---|
| `Ts` | 样本时刻（本地墙钟，取铃响起响点） |
| `RequiredSec` | 本次测得的「让误差归零所需绝对偏移」（秒）；口径恒为**标称边界 − 铃响起响** —— 旁证样本同样如此（旁证样本早先误用内核切换位置当锚，会恒少一个当时的 `CurrentSec`，已修） |
| `CurrentSec` | 测量时的当前偏移（秒）——`RequiredSec` 与它的差就是本次实际改动量 |
| `Kind` / `B` | 边界类型（上课/下课）与课表显示时刻 |
| `Applied` | 本次是否真的写入了偏移（带内不写、离群拒写时为 `false`；分步写入时仍为 `true`——那一步真的写进去了） |
| `Reason` | 判据给出这个结论的**真实原因**（v1.0.5 起）：`applied` 写入过 / `dead-zone` 预测落在死区带内 / `stepped` 分步写入（v1.1.0，本次只走了 ±上限那一步）/ `outlier` 离群拒写（v1.1.0，与稳健拟合差 >2 s）/ `large-error` 旧版的大误差拒写 / `side-schedule` 仅课表窗口命中（旁证）/ `side-conflict` 双窗口冲突（旁证）。旧样本无此字段，按几何关系反推 |

用途有三个：

1. **重启恢复**：插件启动后首次布防时会载入**最近 12 小时**的样本喂给估计器，
   避免进程重启后前几个边界退回「单次测量直接写入」。用时间窗而不是「当天」，是为了让每天早上第一个窗口
   也有前一晚的样本做旁证 —— 10-15 的 08:10 就吃过亏：当天首条样本是脏值（−6.456 s），序列里再没有别的样本，
   它自己成了中位数被直接写了进去（日志 `样本1/离散0.000`）。
   日志会写明 `偏移样本恢复：载入样本 N 个（参与…；跳过更早 M 个）`。
2. **离线分析**：可直接画偏移随时间的变化（`Ts` vs `RequiredSec`），
   或用 `ReplayTool fitter <样本序列文件>` 离线复算不同估计策略的稳定性。
3. **旁证样本不进估计器**（v1.0.5）：`Reason` 为 `side-schedule` / `side-conflict` 的样本**不参与**
   运行时估计器，默认也不参与手动拟合，只作人工复核的线索——它们的坐标来自课表窗口（或一次冲突记录），
   不是开关窗口的测量。它们会照常出现在设置页「样本管理」里，确认可信后手动勾上即可参与拟合。
   同理 `outlier`（离群拒写，v1.1.0）默认不参与；`stepped`（分步写入，v1.1.0）是干净测量，照常参与。
   **离群判定优先于死区判定**（v1.1.0 修正）：一条脏值与「拟合预测值」之差可能恰好落在死区内，
   但它首先是与稳健拟合差 >2 s 的离群值 —— 所以先判离群，`dead-zone` 只留给已过复核的干净测量。

## 离线工具（不随插件打包）

```powershell
dotnet build plugin/tools/TemplateTool/TemplateTool.csproj -c Release
dotnet build plugin/tools/ReplayTool/ReplayTool.csproj -c Release

ReplayTool <dump.wav> <模板目录> <边界在dump内秒数>   # 对已采集的边界录音重跑完整判定链（先模板锚点，再并排打印老行为与 v1.1.0 锚定闸门）
ReplayTool fitter <样本序列文件>                     # 复算偏移估计算法
ReplayTool manual-fit <offset-samples.jsonl> [日期]  # 跑一遍手动拟合：当天有效样本 → 要写入的偏移
ReplayTool gate-reconcile <dump.wav> [当时偏移秒]     # 打印开关窗口/课表窗口两套判据 + 复核结论
ReplayTool gate-scan <Dumps 目录>                    # 全量 dump：旧/新选点对比 + 分歧汇总表
ReplayTool envelope <dump.wav> [步长秒]              # 整段 RMS 包络（这段时间里到底有什么声音）

# 离线断言（全部通过才返回 0）
ReplayTool gate-reconcile-test <Dumps 目录>          # 双窗口复核 12 条真实窗口 + 6 条合成分支断言（4 个杂音窗口必须判冲突）
ReplayTool absolute-required-test                    # 退化口径换算 4 条（残差 + 当前偏移 = 绝对所需偏移）
ReplayTool sample-manage-test                        # 样本管理数据层 22 条（含人工标记与乱行容错）
ReplayTool notify-test                               # 人工审核提醒的开关/阈值判定 7 条
ReplayTool gate-guard <Dumps 目录>                   # 全量 dump：没有任何命中依赖「除以数字静默」的比值
ReplayTool estimate-test                             # v1.1.0 估计器 12 条：离群只标记不清空、连续两条一致才重开、步进限幅与死区
ReplayTool dumps-clear-test                          # 「清除无用录音」的删除与保留判据 20 条（近期 / 断言夹具 / 非 wav / 子目录一律不动）
```

> **全量离线回放（v1.1.0 的验证方式）**：对 `Dumps/` 下全部历史窗口逐个跑上面的根命令，
> 把「模板命中」「老行为闸门」「锚定闸门」三行并排对照。v1.1.0 的实测结论：75 个窗口模板命中 28 个（37%），
> 命中时 20 个与老行为一致（≤0.05 s）、8 个被改动、其中 7 个改动 >6 s（都是老行为落在边界另一侧瞬态上的窗口）。
> 批量脚本形如 `Get-ChildItem Dumps\*.wav | % { ReplayTool $_ <模板目录> <边界秒> -2 20 }`。

## 已知限制

- **校铃自身抖动是误差下限**：同一批边界测得的「所需偏移」本身就有秒级以下的离散，
  因此单一偏移量无法让每个边界都精确对齐；本插件的目标是**中位误差最小且误差不累积**。
- **吵闹窗口会丢一部分测量**（v1.0.5 已改善）：环境噪声较高时起响比值会明显下降，
  现在靠「峰值 ≥ −20 dBFS 且抬升 ≥ 6 dB」的或条件能救回其中一部分，
  但环境声整体盖过铃声时仍会记为「无可信测量」并跳过。
- **模板命中率是硬上限的一部分**（v1.1.0）：实测 37%。未命中的窗口只能靠 ±8 s 闸门，
  因此吵闹窗口仍是主要误差来源；要提高只能换更贴合的样本（同一段铃的多次录音做多模板）或加长观察期。
- **一天内不同时段的最优偏移可能不同**，
  因此估计器用 6 小时窗口，并只在「样本 ≥6 个、跨度 ≥4 小时、残差 <0.6 s」三项同时满足时才启用趋势外推
  （外推上限 24 小时、斜率钳 ±2 s/h；门槛比 v1.0.5 放宽，因为样本段不再被离群值清空，统计更可信）。
- **上下课共用一条偏移序列**（v1.1.0）：偏移是系统属性，与边界类型无关；若日志里两类边界的所需偏移
  长期系统性分家（差 >1 s 且各自稳定），那说明拟合前提不成立（用户 2026-10-15 判定：分家即说明拟合有误），
  应先查铃况与模板，而不是分别拟合。
- 需要麦克风；无设备/无权限时优雅跳过并记日志，不影响 ClassIsland 其它功能。
