# 铃声自动校时（BellTime Calibration）

监听校园广播铃声，自动将 [ClassIsland](https://github.com/ClassIsland/ClassIsland) 的 **应用设置 → 时钟 → 时间偏移** 校准到学校铃声系统时间的 2.x 插件。

> **核心目标**：使 ClassIsland 界面切换上下课的时刻与真实铃声严格对齐。**不修改课表**、**不修改内核**（原版 ClassIsland 即装即用）。

| 项 | 说明 |
|---|---|
| 插件 ID | `belltime.calibration` |
| 当前版本 | **1.2.1.0** |
| 支持平台 | Windows（依赖系统默认麦克风输入设备） |
| 安全机制 | 默认开启「学习模式」：仅记录听铃识别与偏移推算结果，不自动调整时间 |

---

## 解决的问题

学校广播铃声与电脑系统时间常有数秒甚至数十秒的固定偏差或走时漂移。本插件在每个课表上下课时间点前后短暂开启麦克风，**捕捉真实校铃起响时刻**，自动计算所需时间偏差并平滑校准，实现课表状态与上下课广播完美同步。

---

## 工作机制

1. **自动布防**：在上下课时间边界前定时激活监听（默认提前 15 秒，当存在较大历史偏差时会自动延长提前量）。
2. **轻量拾音**：仅在时间边界附近的极短窗口期调用麦克风并在内存中分析，**平时零占用，音频默认不保存**。
3. **精准定点**：
   - **起响沿分析（主判据）**：捕捉突发声音能量起爆点，即使在教室喧闹背景下也能准确回溯长铃声起始点。
   - **双窗口复核**：同时对比「课表基准时间」与「当前换课时间」两侧信号，遇到两处矛盾或环境杂音冲突时自动拒写，杜绝误判。
   - **模板特征匹配（辅助）**：支持导入真实铃声样本提取声学特征，在嘈杂窗口辅助锁定起响位置。
4. **平滑写入与安全防护**：
   - **稳健拟合**：以近期可信样本中位数为基准，过滤瞬时杂音偶发跳变。
   - **死区保护**：偏差小于 0.3 秒时不作微调，避免时钟来回抖动。
   - **分步安全逼近**：单次调整上限默认 3 秒；如遇到校铃大调（偏差 > 3 秒），会自动在后续几个时间点分步对齐，绝不突然大幅改动系统时间。

## 铃声样本（可选增强）

插件的起响沿识别开箱即用；导入本校真实的铃声录音可进一步提升复杂噪音环境下的抗干扰能力。

- **录制要求**：使用装有 ClassIsland 的电脑麦克风，录制响铃时的真实声音（WAV 格式，几秒至几十秒均可）。
- **导入方式**：在 ClassIsland「设置 → 插件 → 铃声自动校时 → 模板匹配（铃声样本）」中，点击「浏览」分别选择上课铃和下课铃音频即可，设置后即时生效。

## 提供你自己的铃声样本（必做）

插件的**主判据「起响沿闸门」不依赖样本**，装好即可工作；样本只用于辅助的模板匹配路径
（在个别窗口能把起响点精确到毫秒级）。所以样本是**可选增强**，但强烈建议提供。

### 录制要求

- 用**本机（装 ClassIsland 的那台电脑）的麦克风**录，位置与日常使用一致；
- 在**正在响铃时**录一段，长度几秒到几十秒都行；开头多录 5~10 秒环境声更好（便于自动截取）；
- 保存为 **WAV**（插件自带 WAV 解析器；`.m4a`/`.mp3` 请先用 ffmpeg 转成 WAV）；
- 上课铃、下课铃**各录一段**（上下课铃音色差别很大，别混用同一段）。

### 导入方式（两种，任选）

**A. 设置页导入（推荐）**
1. 打开 ClassIsland「设置 → 插件 → 铃声自动校时 → 模板匹配（铃声样本）」；
2. 在「上课铃样本」/「下课铃样本」行点 **「浏览…」**，选中你录的 WAV；
3. 若你知道铃声响在录音的第几秒，在下面的「截取区间」填 `起始秒-结束秒`（如 `12.0-14.5`）；
   留空则由插件自动取「最响且持续 ≥1.5 s」的段；
4. 选完立即生效（设置页会主动重载模板库，无需重启），日志会打印 `已选择铃声样本：… 模板库已重载（已加载 N 个模板）`。

**B. 直接放文件**
把你截好的 2.5 s 模板放到插件配置目录的 `Templates/` 下，命名含「上课」/「下课」即可
（如 `上课铃.wav`、`下课铃.wav`），重启 ClassIsland。随包的两个同名文件是**静音占位**，
插件会识别并跳过它们（日志：`跳过 上课铃.wav：全零静音（随包占位文件…）`），直接覆盖即可。

### 验证样本是否可用

```powershell
# 用生产的匹配器在录音上自测（同源应接近 1.000）
TemplateTool selftest plugin/Templates/上课铃.wav 你的录音.wav 0.6 0.45 15
```

`tools/README.md` 里有完整的工具用法与标定建议。

## 构建与安装

```powershell
dotnet build plugin/BellTimeCalibration.csproj -c Release     # 输出 plugin/bin/Release/net8.0/
dotnet build plugin/tools/TemplateTool/TemplateTool.csproj -c Release
dotnet build plugin/tools/ReplayTool/ReplayTool.csproj -c Release
```

安装：把 `bin/Release/net8.0/` 下的 `manifest.yml` + `BellTimeCalibration.dll` + `BellTimeCalibration.deps.json`
+ `SoundFlow.dll` + `miniaudio.dll` 复制到 ClassIsland 数据目录的 `Plugins/belltime.calibration/`，重启 ClassIsland。
首次使用需在系统设置中授予 ClassIsland 麦克风权限。

> 部署前必须先停止 ClassIsland 进程，否则 DLL 被占用。

## 配置与调参

设置项见 `plugin/README.md`。关键几项：

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用铃声自动校时 | 开 | 总开关：关掉后不监听、也不自动应用。设置页的「手动拟合并应用」按钮不受它约束（显式手动动作） |
| 学习模式 | 开 | 只记录不写；确认稳定后关闭 |
| 自动应用校准偏移 | 关 | 关闭学习模式后才生效 |
| 单次写入上限 | 3 秒 | 一次要改的偏移超过此值时**只写 ±此值**（分步逼近，`reason=stepped`）；同时决定是否弹人工复核提醒。改完即生效 |
| 人工审核提醒 | 开 | 关掉后「分步写入」与「双窗口冲突不写」都仍然照旧发生，只是都不再弹提醒（只记日志） |
| 布防提前秒数 / 铃响搜索半窗 | 15 / 12 秒 | v1.1.0 起两者都是**下限**：实际 `clamp(max(配置值, \|当前偏移\|+10s), 配置值, 60s)` 与 `max(配置值, \|当前偏移\|+8s)` —— 偏移超过 20 s 时铃才落得进窗口/搜索区间 |
| 样本管理（设置页卡片） | — | 逐条复核当天样本是否有效；作废的样本不再参与手动拟合（不影响自动应用链路）；「判据位置」列显示**当时真实的原因**（v1.0.5 起，v1.1.0 增 `outlier`/`stepped`），旁证与离群样本默认不勾；「当时偏移」列显示该次测量当时生效的偏移值（= 记录里的 `CurrentSec`，拟合的**输入侧**），不是这条样本算出来的「所需偏移」（`RequiredSec`）——同一段窗口里没写偏移的几条会显示同一个值，属正常；v1.1.1 起「当时偏移」「采用偏移」两列均两位小数，「采用偏移」= 当前勾选 + 本行纳入拟合后的写入值（勾选变化实时重算） |
| 起响沿闸门参数 | 内建常量 | `OnsetGate.GateSeconds=8.0`（2026-10-12 由 2.0 加宽：半窗必须宽于插件的偏移误差，否则真铃落在窗外、只能抓到房间噪声）、`RatioMin=4.0`、`DominanceDb=6.0`（支配门：一侧强出 >6 dB 就用那一侧的坐标，v1.0.5 补对称）、`AgreeSeconds=1.0`（双窗口一致性容差）、`SameStrengthDb=2.0`（两窗口峰值差 ≤2 dB 判为同一段长铃的先后两击；差距落在 2~6 dB 中间带才判冲突，v1.0.5）、`LoudPeakDb=−20`、`MinRiseDb=6.0`（「高声压起响」或条件，v1.0.5）、`SegmentLookbackSeconds=8.0`、`SegmentDropDb=12.0`、`SegmentHoldSeconds=1.2`（长铃起点回溯，v1.0.5）、`AttackWindowSeconds=0.05`（起声归位：回溯后的坐标再走到真的进声那一刻，v1.0.5）、`AbsoluteMinRms≈−50 dBFS` |

日志：

- `<插件配置目录>/Logs/belltimecalibration-<日期>.log`（人类可读）
- `<插件配置目录>/Logs/calibration-history.jsonl`（结构化，每窗口一行，含结局、起响点、误差、门控结果）
- `<插件配置目录>/Logs/offset-samples.jsonl`（**偏移样本序列**，见下）
- `DebugDumpAudio=true` 时窗口音频转存到 `<插件配置目录>/Dumps/`（**默认关闭**，音频平时只在内存）；设置页同一张卡片里的「清除无用录音」用来收拾越攒越多的调试录音，但它只删**确实无用**的那些：**7 天以内的一律保留**（排障还要看），离线断言（`ReplayTool gate-reconcile-test`）点名用到的录音**永久保留**，文件名认不出时刻的也保留；只删 `Dumps/` 下一层的 `*.wav`，模板与样本记录不受影响

### 偏移样本序列（`offset-samples.jsonl`）

每个拿到**可信测量**的监听窗口追加一行，记录参与偏移估计的样本：

```json
{"Ts":"2026-09-15 08:10:21.683","RequiredSec":-1.6850,"CurrentSec":-1.3440,"Kind":"上课","B":"08:10:00.001","Applied":true,"Reason":"applied"}
```

| 字段 | 含义 |
|---|---|
| `Ts` | 样本时刻（本地墙钟，取铃响起响点） |
| `RequiredSec` | 本次测得的「让误差归零所需绝对偏移」（秒）；口径恒为**标称边界 − 铃响起响** —— 旁证样本同样如此（旁证样本早先误用内核切换位置当锚，会恒少一个当时的 `CurrentSec`，已修） |
| `CurrentSec` | 测量时的当前偏移（秒）——`RequiredSec` 与它的差就是本次实际改动量。设置页样本管理的「当时偏移」列显示的就是它（v1.1.0 修订：此前那一列显示的是 `RequiredSec`，与列名「所需偏移」同义、却不是测量所依据的偏移；v1.1.1 起显示两位小数） |
| `Kind` / `B` | 边界类型（上课/下课）与课表显示时刻 |
| `Applied` | 本次是否真的写入了偏移（带内不写、离群拒写时为 `false`；分步写入时仍为 `true`——那一步真的写进去了） |
| `Reason` | 判据给出这个结论的**真实原因**（v1.0.5 起）：`applied` 写入过 / `dead-zone` 预测落在死区带内 / `stepped` 分步写入（v1.1.0，本次只走了 ±上限那一步）/ `outlier` 离群拒写（v1.1.0，与稳健拟合差 >2 s）/ `large-error` 旧版的大误差拒写 / `side-schedule` 仅课表窗口命中（旁证）/ `side-conflict` 双窗口冲突（旁证）。旧样本无此字段，按几何关系反推 |

用途有三个：

1. **重启恢复**：插件启动后首次布防时会载入**最近 12 小时**的样本喂给估计器，
   避免进程重启后前几个边界退回「单次测量直接写入」。用时间窗而不是「当天」，是为了让每天早上第一个窗口
   也有前一晚的样本做旁证 —— 10-15 的 08:10 就吃过亏：当天首条样本是脏值（−6.456 s），序列里再没有别的样本，
   它自己成了中位数被直接写了进去（日志 `样本1/离散0.000`）。
   日志会写明 `样本 当天 N（参与…） 导入M｜中位…s(K)`。
   **谁会被捞回来**（v1.1.0.0 收严，口径见 `OffsetSampleStore.IsSeedableForRuntime`）：判据采信过的测量（写入过 / 死区带内 / 步进）
   照常；**旁证样本**与**判据已判脏值拒写的样本**（`outlier` / 旧版 `large-error`）**不喂给运行时估计器** ——
   2026-10-16 首窗实测：前一晚两条 `outlier`（−6.395 / −6.427）原会被当成普通测量恢复回来，把恢复中位数从 −0.11 s 拖到 −3.359 s。
   旧数据（无 `Reason` 字段、原因未记）无法判定，仍按普通测量处理。人工在样本管理里勾上的拒写样本仍可参与**手动拟合**（两处口径刻意不同）。
2. **离线分析**：可直接画偏移随时间的变化（`Ts` vs `RequiredSec`），
   或用 `ReplayTool fitter <样本序列文件>` 离线复算不同估计策略的稳定性。
3. **旁证样本不进估计器**（v1.0.5）：`Reason` 为 `side-schedule` / `side-conflict` 的样本**不参与**
   运行时估计器，默认也不参与手动拟合，只作人工复核的线索——它们的坐标来自课表窗口（或一次冲突记录），
   不是开关窗口的测量。它们会照常出现在设置页「样本管理」里，确认可信后手动勾上即可参与拟合。
   同理 `outlier`（离群拒写，v1.1.0）默认不参与；`stepped`（分步写入，v1.1.0）是干净测量，照常参与。
   **离群判定优先于死区判定**（v1.1.0 修正）：一条脏值与「拟合预测值」之差可能恰好落在死区内，
   但它首先是与稳健拟合差 >2 s 的离群值 —— 所以先判离群，`dead-zone` 只留给已过复核的干净测量。

## 已知限制

- **校铃自身抖动是误差下限**：同一批边界测得的「所需偏移」本身就有秒级以下的离散，
  因此单一偏移量无法让每个边界都精确对齐；本插件的目标是**中位误差最小且误差不累积**。
- **吵闹窗口会丢一部分测量**（v1.0.5 已改善）：环境噪声较高时起响比值会明显下降，
  现在靠「峰值 ≥ −20 dBFS 且抬升 ≥ 6 dB」的或条件能救回其中一部分，
  但环境声整体盖过铃声时仍会记为「无可信测量」并跳过。
- **模板命中率是硬上限的一部分**（v1.1.0）：实测 37%。未命中的窗口只能靠 ±8 s 闸门，
  因此吵闹窗口仍是主要误差来源；要提高只能换更贴合的样本（同一段铃的多次录音做多模板）或加长观察期。
- **一天内不同时段的最优偏移可能不同**，
  因此估计器用 6 小时窗口，并只在「样本 ≥6 个、跨度 ≥4 小时、残差 <0.6 s」三项同时满足时才启用趋势外推
  （外推上限 24 小时、斜率钳 ±2 s/h；门槛比 v1.0.5 放宽，因为样本段不再被离群值清空，统计更可信）。
- **上下课共用一条偏移序列**（v1.1.0）：偏移是系统属性，与边界类型无关；若日志里两类边界的所需偏移
  长期系统性分家（差 >1 s 且各自稳定），那说明拟合前提不成立（用户 2026-10-15 判定：分家即说明拟合有误），
  应先查铃况与模板，而不是分别拟合。
- 需要麦克风；无设备/无权限时优雅跳过并记日志，不影响 ClassIsland 其它功能。
