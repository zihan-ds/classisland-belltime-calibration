# 铃声自动校时（BellTime Calibration）

监听校园广播铃声，自动将 ClassIsland 的 **应用设置 → 时钟 → 时间偏移** 校准到学校铃声系统时间的 2.x 插件。

> **核心目标**：使 ClassIsland 换课提示与实际广播铃声严格对齐。**不修改课表**、**不修改内核**（原版 ClassIsland 即装即用）。

| 项 | 说明 |
|---|---|
| 插件 ID | `belltime.calibration` |
| 当前版本 | **1.2.1.0** |
| 支持平台 | Windows（需系统默认麦克风输入权限） |
| 安全机制 | 默认开启「学习模式」：仅记录识别结果与偏移推算，不自动调整时间 |

---

## 解决的问题

学校作息钟与电脑系统时间常有数秒乃至数十秒偏差。本插件在课表上下课时间点前后短暂开启麦克风，**捕捉真实校铃起响时刻**，推算所需时间偏差并平滑校准，使界面课表与广播铃声完美同步。

---

## 工作机制

1. **自动布防**：在上下课时间边界前定时激活监听（默认提前 15 秒，当存在较大历史偏差时会自动延长提前量）。
2. **轻量拾音**：仅在时间边界附近的极短窗口期调用麦克风并在内存中分析，**平时零占用，音频默认不保存**。
3. **精准定点**：
   - **起响沿分析（主判据）**：捕捉突发声音能量起爆点，即使在教室喧闹背景下也能准确回溯长铃声起始点。
   - **双窗口复核**：同时对比「课表基准时间」与「当前换课时间」两侧信号，遇到两处矛盾或环境杂音冲突时自动拒写，杜绝误判。
   - **模板特征匹配（辅助）**：支持导入真实铃声样本提取声学特征，在嘈杂窗口辅助锁定起响位置。
4. **平滑写入与安全防护**：
   - **稳健拟合**：以近期可信样本中位数为基准，过滤瞬时杂音偶发跳变。
   - **死区保护**：偏差小于 0.3 秒时不作微调，避免时钟来回抖动。
   - **分步安全逼近**：单次调整上限默认 3 秒；如遇到校铃大调（偏差 > 3 秒），会自动在后续几个时间点分步对齐，绝不突然大幅改动系统时间。

---

## 铃声样本（可选增强）

插件的起响沿识别开箱即用；导入本校真实的铃声录音可进一步提升复杂噪音环境下的抗干扰能力。

- **录制要求**：使用装有 ClassIsland 的电脑麦克风，录制响铃时的真实声音（WAV 格式，几秒至几十秒均可）。
- **导入方式**：在 ClassIsland「设置 → 插件 → 铃声自动校时 → 模板匹配（铃声样本）」中，点击「浏览」分别选择上课铃和下课铃音频即可，设置后即时生效。

## 日志与记录

所有校准历史与推算记录保存在插件配置目录：

## 单次写入上限与人工复核提醒（v1.1.0 起为分步写入）

一次要写入的偏移与当前偏移相差超过上限时，插件只写 `±上限` 这一步（`reason=stepped`），
并弹出一条提醒：边界时刻、当前偏移、本次测得的所需偏移与差值，提示还需几个窗口走完。

- 差值在限内时照旧一次写入（`reason=applied`），不弹提醒；
- 只在**真的分步**时出现；**没有时间冷却**——同一个大差值每次都提醒；
- 由设置项**「人工审核提醒」**（默认开）控制：关掉后仍然照常分步写入，但不再弹提醒、只记日志
  （限幅是数据安全底线，提醒只是可选的打扰，两者分开）；
- 出现在 ClassIsland 的提醒通道里，可在**设置 → 提醒 → 铃声校时复核**单独关闭，或在同一页的**高级设置**里
  给它单独配提醒音 / 强调特效 / 置顶；
- 「设置 → 提醒 → 铃声校时复核 → **基本设置**」里有一份**同样的设置面板**（人工审核提醒开关 + 发送测试提醒），
  与设置页里那两个是**同一份配置**，改哪边都一样；该面板由插件在 UI 线程创建，创建失败只退回「没有设置」并记日志；
- 有**「发送测试提醒」**按钮，可随时确认提醒能正常弹出（该测试不受开关约束）；
- 提醒走宿主已有的提醒主机服务（公开实例 + 反射调用其 internal 发送方法），**不需要任何内核改动**。

> 被静默拦下的偏差，用户根本不知道要去看日志——所以这条路径必须有出口。

## 手动拟合（设置页「手动拟合并应用」）

按下后：读当天已落盘样本 → **只保留勾选「参与拟合」的样本**（默认：判据写入过的、以及
**落在死区带内没写入的**都参与，离群（`outlier`）的不参与；人工勾选结论优先）→ 用与运行时**完全相同**的估计器（近 6 小时中位数，
趋势外推仅在样本数/跨度/残差三门槛同时满足时启用）重算 → **立即写入「应用设置 → 时钟 → 时间偏移」**。
**无视学习模式与自动应用开关**（显式手动动作，按下即写）。

写入后会把当天样本重新装进运行时估计器，避免下一个边界用旧序列把手动结果顶回。
结果文字写在按钮旁（写入前后值、有效样本数、中位数、散度、趋势是否启用），日志同样留痕。
离线复算：`ReplayTool manual-fit <offset-samples.jsonl> [日期]`。

## 样本管理（人工复核）

设置页「样本管理」卡片列出**当天**每条样本（铃响时刻 / 类型 / 课表边界 / 当时偏移 / 采用偏移 / 判据写入 / 判据位置 / 参与拟合），
勾选框可逐条改。**勾选 = 参与手动拟合，取消勾选 = 不参与；人工设为有效的一律参与，无论当初是否被写入过。**
「当时偏移」列（v1.1.0 修订，v1.1.1 起两位小数）显示该次测量**依据的偏移量**——也就是这条样本行里的 `CurrentSec`、使用者手填进
「时间偏移」的那个数；它不是这条样本算出来的「所需偏移」（`RequiredSec` = 标称边界 − 铃响起响，那个值只出现在
拟合结果与日志里）。两者之差才是本次的实际改动量，所以同一段窗口里没写偏移的几条样本会显示同一个「当时偏移」。
「采用偏移」列（v1.1.1）显示在当前勾选基础上把本行也纳入拟合后，手动拟合并应用会写入的值（两位小数）：
已勾选行显示当前拟合结果，未勾选行显示勾上后的结果，勾选变化立即重算。手动拟合取最近 6 小时窗口
（不足 3 条才放宽到全部）：窗口外的行通常不改变预览；窗口内按中位数变化，只有中位数恰好不变时才不变。手动拟合与自动应用的所有实际写入也统一取两位小数。
默认勾选：判据写入过的勾选，**落在死区带内没写的、以及分步写入（`stepped`）的也勾选**（同样是干净测量），
离群（`outlier`）默认不勾选；人工结论优先。
「判据位置」一列直接标出每条属于哪一类，默认勾不勾一眼可见：**写入过** / **死区带内（未写）** / **步进写入** /
**离群拒写** / **仅课表命中（旁证）** / **双窗口冲突（旁证）**（v1.0.5 起判据在落盘时把真实原因一并写进样本行 `Reason`；
旧样本没有该字段，按「|所需偏移 − 当时偏移| ≤ 死区」反推并注明「旧数据，原因未记」——上一版正是这样把 6 条
「预测落在死区所以没写」误标成了「大误差拒写」；v1.0.5 的 `large-error` 在 v1.1.0 变为步进写入
（`stepped`，仍是干净测量），旧样本里的 `large-error` 保持「人工复核过再说」的默认不勾选）。**离群判定优先于死区判定**（v1.1.0 修正）：脏值与「拟合预测值」之差有时恰好落在死区内，
但它首先是与稳健拟合差 >2 s 的离群值 —— 先判离群，`dead-zone` 只留给已过复核的干净测量
（否则脏值会被显示成「死区带内（未写）」并按默认口径勾上）。**旁证样本默认不参与**：
它们的坐标来自课表窗口（或一次冲突记录），
不是开关窗口的测量，确认可信后手动勾上即可纳入手动拟合。

- 人工标记只作用于**手动拟合**的样本筛选，不改动估计器算法，也不影响自动应用链路的内部样本序列；
- 结论落在旁挂文件 `Logs/sample-exclusions.jsonl`（每行 `{"Ts":"…","Invalid":true}`），
  不重写只追加的 `offset-samples.jsonl`；删掉旁挂文件即恢复「全部有效」；
- 离线断言：`ReplayTool sample-manage-test`。

## 校准结果如何应用（通道：应用设置 → 时钟 → 时间偏移）

| 通道 | 说明 |
|---|---|
| **应用设置 → 时钟 → 时间偏移** | 即内核设置项 `Settings.TimeOffsetSeconds`。插件经 `IAppHost.Host`（public static IHost）在宿主 DI 中取到内核 `SettingsService`，反射读取/写入其 `Settings.TimeOffsetSeconds`——**原版内核即可用，无需任何内核改动**。写入后立即生效（宿主每次取时间都会读该设置）、由 `SettingsService` 自动落盘 `Settings.json`、设置页「时钟 → 时间偏移」同步可见 |

> ⚠️ 写偏移是**绝对写入**（写入「所需偏移」），会覆盖你之前在 ClassIsland 里手动设置的时间偏移——这正是「跟随校铃」的语义。
>
> ⚠️ 插件任何情况下都**不修改课表档案**（只写时间偏移，不碰时间表），也**不依赖任何内核补丁**，原版内核即可运行。

## 系统要求

- ClassIsland **2.x**（插件 apiVersion 2.0.0.0）
- Windows（miniaudio/WASAPI），需要可用的默认输入设备（麦克风）
- 首次使用需在系统设置中授予 ClassIsland **麦克风权限**，否则窗口期采到全静音，窗口会被判作无效跳过
- **自动应用**额外要求宿主内核含可写偏移属性（`TimeOffsetSeconds`/`OffsetSeconds`），否则仅学习模式记录可用

## 安装

把 `BellTimeCalibration-<版本>.cipx` 拖入 ClassIsland「设置 → 插件」安装；或手动把 `manifest.yml` +
`BellTimeCalibration.dll` + `BellTimeCalibration.deps.json` + `SoundFlow.dll` + `miniaudio.dll` 复制到
ClassIsland 数据目录的 `Plugins\belltime.calibration\`（安装版默认在 `data\Plugins\belltime.calibration\`）后重启 ClassIsland。
主日志出现 `铃声自动校时(belltime.calibration,<版本>)` 即加载成功。首次使用需在系统设置中授予 ClassIsland 麦克风权限。

> **本插件不自带铃声样本。** 随包的 `Templates\上课铃.wav`、`Templates\下课铃.wav` 是**静音占位**，
> 启动日志会显示「跳过 …：全零静音（随包占位文件…）」。请按下节导入你自己录的铃声样本，模板匹配才会启用。
> 主判据「起响沿闸门」不依赖样本，未导入样本时插件照常工作（只是少了毫秒级精定位这一路辅助）。

## 提供你自己的铃声样本

铃声音色每所学校都不同，必须自行录制。摘要（完整说明见仓库根目录 `README.md`）：

- 用**装 ClassIsland 那台电脑的麦克风**、在真实响铃时录一段 WAV（几秒到几十秒，开头多留些环境声更好）；
- 上课铃、下课铃**各录一段**（两者音色差别很大，不可混用同一段）；`.m4a`/`.mp3` 需先用 ffmpeg 转 WAV；
- **设置页导入（推荐）**：设置 → 插件 → 铃声自动校时 →「模板匹配（铃声样本）」→ 点「浏览…」选中录音，
  需要时填「截取区间」（如 `12.0-14.5`，留空=自动取最响且持续 ≥1.5 s 的段）；选完**立即生效**，日志会打印
  `已选择铃声样本：…模板库已重载（已加载 N 个模板）`；
- **直接放文件**：把截好的 2.5 s 模板放到插件配置目录 `Templates\`（文件名含「上课」/「下课」），重启 ClassIsland。

## 快速上手

1. 安装后**保持学习模式开启**，正常使用数日。
2. 每次边界若识别到铃声，插件日志会记录 `检测到铃声 → t_ring / delta`。
3. 核对 delta 是否符合预期（对齐良好时应趋近 0；稳定为一个非零值说明本机时间与校铃时钟存在固有偏差，该值即期望的偏移量；忽大忽小则多为环境误检）。
4. 确认合理后：在插件设置页**关闭学习模式**，再开启「自动应用校准偏移」。

## 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用铃声自动校时 | 开 | 总开关，关闭后不监听、也不自动应用校准结果。唯一的例外是设置页的「手动拟合并应用」按钮：它是一次显式手动动作，不受本开关约束 |
| 学习模式 | **开** | 只记录识别结果，不应用偏移 |
| 自动应用校准偏移 | 关 | 需先关闭学习模式才生效；且要求宿主内核含可写偏移属性（`TimeOffsetSeconds`/`OffsetSeconds`），否则自动应用停用、仅学习记录 |
| 布防提前秒数 | 15 | 距时间边界多少秒开始布防监听。**v1.1.0 起这是下限**：实际取 `clamp(max(本项, \|当前偏移\| + 10 s), 本项, 60 s)`，偏移超过它时自动加长，保证「铃在这个窗口里」（用户实测偏移可能超过 20 s） |
| 边界后监听秒数 | 8 | 越过边界后继续监听多少秒 |
| 铃响搜索半窗（±秒） | 12 | **模板路径**的搜索半窗。v1.1.0 起这是**下限**：实际取 `max(本项, \|当前偏移\| + 8 s)`，与布防提前量同公式，避免偏移大时铃落在搜索区间外。它同时用于「模板兜底测量」（闸门都没命中时）与模板锚点搜索；闸门自己的半窗是内建常量 `OnsetGate.GateSeconds`(8 s)（有锚点时收窄为 `AnchorApertureSeconds`(3 s)），不受本项影响。长铃还会再向前回溯最多 8 s 找这段声音的起点 |
| 应用死区（秒） | 0.3 | 偏移估计值（近期样本中位数）与当前偏移之差小于此值时不动作，否则写入。0.3 s 是把稳态误差压进 0.5 s 的取值；校铃自身的抖动是残余误差的物理下限 |
| 识别灵敏度 | 2.0 | 突发能量判定为「有铃声」所需超过环境噪声底的倍数（`RingDetector.cs:79`；越大越严格，越小越容易把环境声当铃） |
| 单次写入上限（秒） | 3 | 一次要改的偏移超过此值时**只写 ±此值**（分步逼近，`reason=stepped`）并弹出人工复核提醒（1~120 s，改完即生效）；它同时是「是否提醒」的判据。**不再拒写**：所需偏移超过 20 s 时，靠接连几个边界走完。离群测量（与稳健拟合差 >2 s）另有独立判据，与本项无关 |
| 人工审核提醒 | 开 | 关掉后「分步写入」与「双窗口冲突不写」仍然照旧发生，只是都不再弹出界面提醒（只记日志）。分步限幅不受此开关影响 |

以上设置持久化于 `BellCalibrationSettings.json`（插件配置目录，改动即自动保存）。

## 隐私与安全

- **绝不常驻监听**：麦克风仅在「边界前布防秒数 + 边界后监听秒数」的窗口期内临时启用，其余时间零占用（Windows 任务栏可观察到窗口期的麦克风指示）。
- **默认不落盘**：音频只在内存里做 RMS 突发检测与起响沿分析，默认不写任何音频文件。唯一的例外是设置页「调试音频转存」（`DebugDumpAudio`）：开启后每个监听窗口的音频会写成 `<插件配置目录>\Dumps\*.wav`，仅用于核对铃声识别结果与重建模板，默认关闭。转存文件插件运行期不读回，只会随窗口越攒越多，因此同一张卡片里另有一个**「清除无用录音」按钮**：点两次（第一次报将删除的数量与体积、以及保留几个）删掉 `Dumps\` 下**确实无用**的调试录音——**7 天以内的一律保留**（排障还要看），离线断言（`gate-reconcile-test`）点名用到的录音**永久保留**，文件名认不出时刻的也保留；只删该目录下一层的 `*.wav`，铃声模板（`Templates\`）、样本记录、配置与日志一律不动。
- 麦克风被占用 / 无设备 / 无权限时优雅跳过本窗口并记日志，不影响 ClassIsland 其它功能。

## 日志与排查

- 插件日志：`<插件配置目录>\Logs\belltimecalibration-<日期>.log`（安装版默认 `data\Config\Plugins\belltime.calibration\Logs\`）。
- **校准历史（结构化）**：`<插件配置目录>\Logs\calibration-history.jsonl`——每个监听窗口终结时追加一行 JSON（协议 v1），含配置快照、布防/越界墙钟时刻、捕获结局（`skipped-busy`/`init-failed`/`silent-window`/`no-burst`/`no-trusted-match`（闸门与模板都没命中）/`match-conflict`（**双窗口复核判冲突：本次不写入偏移、只落一条旁证样本**）/`no-ring`/`detected``/`error`；`silent-window`=整窗静默被作废、`no-trusted-match`=闸门与模板均未命中）、全部原始突发候选（含开麦静置伪影，便于复核）、噪声底/峰值 dB、delta/shift 与门控结果。供后续离线调参分析（灵敏度/容差/布防提前量/窗口/死区）。
- 启动时应依次看到：初始化 → 调度器已启动 → `应用设置·时间偏移 可用：已解析到设置项 Settings.TimeOffsetSeconds…` + `应用通道选定：应用设置·时间偏移`（唯一通道；原版内核即可用）→ 执行器就绪；解析失败则见 `[WARN] 应用设置·时间偏移 不可用…`（此时自动应用停用，仅学习模式记录）。
- **偏移样本序列**：`<插件配置目录>\Logs\offset-samples.jsonl`——每次测量追加一行（`Ts` / `RequiredSec` / `CurrentSec` / `Kind` / `B` / `Applied` / `Reason`；`Reason` 为 v1.0.5 新增的「判据位置」）。三个用途：① 进程重启后载入**最近 12 小时**的样本喂给估计器，避免重启后前几个边界退回「单次测量直接写入」；用时间窗而不是「当天」，是为了让每天早上第一个窗口也有前一晚的样本做旁证（否则当天首条样本若是脏值，它会自己成为中位数并被写进去）（日志：`样本 当天 N（参与…） 导入M｜中位…s(K)`）——**进食口径**（v1.1.0.0 收严）：旁证样本与判据已判脏值拒写的样本（`outlier` / 旧版 `large-error`）都**不进**运行时估计器，口径见 `OffsetSampleStore.IsSeedableForRuntime`（起因：10-16 首窗把前一晚两条 `outlier` 恢复回来，中位数被从 −0.11 s 拖到 −3.359 s）；② 离线画偏移走势、复算估计策略（`ReplayTool fitter <样本序列文件>`）；③ 旁证样本（`Reason` = `side-schedule` 仅课表窗口命中 / `side-conflict` 双窗口冲突）**不进估计器**、在设置页样本管理里默认不参与手动拟合，仅供人工核对铃况。
- 每次有效铃后会看到一行 `[校时] 拟合 所需X 当前Y 预测Z 差D 样本N/离散S → 写入|带内不写`，即「测量 → 拟合 → 写入」的完整判定过程。
- 若某边界日志为「在忽略列表内，本次不监听、不校准」，即命中 `IgnoredBoundaries`（**默认为空 = 每个边界都监听**；只有某几个边界反复测不到时才建议填入）。
- 若某边界日志为「无突发能量」，多为窗口期内没有实际铃响或麦克风权限问题，属正常作废。
- 若插件未加载：检查 manifest 的 `apiVersion` 需 ≥ 2.0.0.0，且插件目录内 `BellTimeCalibration.dll` / `SoundFlow.dll` / `miniaudio.dll` 齐备。

## 已知限制与路线

- **自触发**：若 ClassIsland 自身被设置为在边界放铃，其铃声理论上可能被本机麦克风拾取并当作校铃。建议在正式采用前留意日志来源，并用设置页「调试音频转存」抽查一个窗口。
- **模板命中率有限（实测 37%）**：模板只在能听出「这段波形就是我们的铃」时给锚点，未命中就退回 ±8 s 闸门；
  因此**吵闹窗口仍是误差的主要来源**（10-14 那天的 09:40 / 10:10 都落在这里）。要进一步提高，
  需要更贴合的铃声样本（同一段铃的多次录音做多模板）或更长的观察期。
- **上下课共用一条偏移序列（v1.1.0）**：若日志里两类边界的「所需偏移」长期系统性分家（差 >1 s 且各自稳定），
  那说明拟合前提不成立（用户 2026-10-15：误差规律不因上下课分家，分家即说明拟合有误），应先查铃况与模板，
  而不是分别拟合。
- **铃声样本需自行录制导入**：`tools/TemplateTool` 可从长录音提取模板，设置页「浏览…」直接导入；未提供样本时模板路径不启用，主判据照常工作。
- 学习模式需要数日真实数据才能评估跨天收敛效果。
- **无需任何内核改动**：插件直接写内核设置项 `Settings.TimeOffsetSeconds`，原版内核即可运行。

## 从源码构建

```
dotnet build -c Release          # 输出 bin\Release\net8.0\
```

- 工程引用 `ClassIsland.PluginSdk 2.0.0.2`（`ExcludeAssets=runtime`）与 `SoundFlow 1.4.1`。
- 由于 SDK 的 `ExcludeAssets=runtime` 会沿依赖闭合压制托管运行时拷贝，csproj 对 `SoundFlow.dll` 与 `miniaudio.dll` 做了显式拷贝（含根因注释）——不要删这两行。
- `.cipx` 打包（v1.1.0.0 起由 SDK 自带的打包目标生成，**不在本机手工压 zip**）：
  `dotnet build plugin/BellTimeCalibration.csproj -c Release -p:CreateCipx=true` → 产物 `plugin/cipx/BellTimeCalibration.cipx`
  （同时生成 `plugin/cipx/checksums.md`，里面的 MD5 就是市场索引要的 `CLASSISLAND_PKG_MD5`）。
  CI 里同一条命令；打 `a.b.c.d` 形式的 tag 时由 `.github/workflows/release.yml` 自动发 Release 并附上这个 `.cipx`。
