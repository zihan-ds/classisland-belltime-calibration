# tools —— 离线工具（不随插件打包）

## TemplateTool

复用插件**生产代码**（`Services/WavReader.cs`、`BellTemplate.cs`、`TemplateMatcher.cs` 直接链接编译），
用于定位录音里的铃声事件、截取模板，并验证匹配算法的分离度。

### 构建

```
dotnet build tools/TemplateTool/TemplateTool.csproj -c Release
# 产物：tools/TemplateTool/bin/Release/net8.0/TemplateTool.exe
```

### 定位铃声事件（调参第一步）

```
TemplateTool scan <录音.wav> [边界相对峰值dB=12]
```

输出「事件起止 / 时长 / 峰值 dB」与「自动截取落点」，退出码 3 = 没找到够长的铃声事件。
判据：阈值 = 包络峰值 − N dB → 取超阈值连续段 → 合并间隔 ≤0.35 s 的段为一次事件 →
在时长 ≥0.45 s 的事件里取峰值最高者（若更早处还有峰值相差 3 dB 内的事件，起点前移到它，覆盖一次铃的首下击打）。

### 从长录音提取模板

```
TemplateTool extract <样本.wav> <输出模板.wav> [起始秒-结束秒] [时长秒=2.5]
```

- 区间留空 = 走上面的自动定位（并打印定位结果与警告）；
- 输出统一为 48 kHz 单声道 PCM16，已去直流 + 峰值归一化；
- 非 WAV 样本（如手机录音 .m4a/.mp3）需先转成 WAV，例如：
  `ffmpeg -y -i 下课铃样本.m4a -ac 1 -ar 48000 -c:a pcm_s16le 下课铃样本.wav`

### 自测（匹配分离度）

```
TemplateTool selftest <模板.wav> <录音.wav> [nccMin=0.6] [specMin=0.45] [探针半径秒=0.2]
```

沿录音以 0.5 s 步长探测，打印每个探针的**真实对齐点**、NCC 与音色相似度，并给出
「最佳匹配 / 命中数 / 非最佳位置平均 NCC / 分离度」。退出码 0 = 最佳位置命中，3 = 未命中或无法探测
（录音短于模板时不再抛异常，改为提示）。

> **探针半径决定你读到的 NCC**：默认 ±0.2 s 只为定位，跨不过铃声攻击沿，NCC 会被系统性低估
> （同一段录音、同一位置，小半径会系统性低估）。要读「插件会遇到的那个 NCC」，
> 把半径放大到覆盖整段（如 `15`），此时所有探针都会收敛到同一个对齐点。


## 判据组合与标定思路

内建在代码里的判据组合：**模板锚点（v1.1.0，命中时）→ 锚 ±3 s 时间门 + 起响比值 ≥4×**（`OnsetGate`，主判据；
无锚点时退回**窗口中心 ±8 s** 时间门 —— 半窗 2026-10-12 由 2 s 加宽，它必须宽于插件的偏移误差，
否则真铃落在窗外，闸门只能抓到 −40 dB 量级的房间噪声，且结果看起来还像一次正常的小修正）；
模板匹配本身作为辅助判据，必须同时通过 NCC、音色、攻击沿三道校验。

判据为什么这样定：

- **精确波形模板不能作为主判据**：同一段铃声在不同边界录到的波形互相关很低，跨边界的波形对齐不可靠；
- **「突然起响」比「像不像模板」稳**：真铃是突然起响（起响比值高），渐强的环境声也可能凑出伪匹配，但比值明显更低；
- **上下课铃跨类区分不难**：两类铃的音色差异通常远大于同类的正常波动，阈值主要用于拒异类声；
- **静音守卫下限**：整窗未进音时「噪声除噪声」也能凑出很高的假比值，故对基线的绝对电平另设下限。

v1.0.5 的三条补充：

- **高声压起响「或」条件**：环境一吵，起响对比度就不可达——基线被抬高后真铃的起响比值明显下降，
  但绝对峰值仍是真铃量级。于是判据改成「比值 ≥4×」**或**「峰值 ≥ `LoudPeakDb`(−20 dBFS)
  且相对基线抬升 ≥ `MinRiseDb`(6 dB)」；它只增不减，也不触碰 `AbsoluteMinRms` 那条「数字静默」排除
  （`gate-guard` 可验证没有任何命中依赖「除以数字静默」的比值）。
- **长铃起点回溯**：多击长音的峰值常落在第二、三击上；命中后若发现当前点之前还有
  同段声音（向前最多 `SegmentLookbackSeconds`=8 s、回落不超过 `SegmentDropDb`=12 dB、并连续保持
  `SegmentHoldSeconds`=1.2 s），就把坐标回溯到这段声音的起点。
- **起声归位（v1.0.5）**：回溯用的是「后 0.5 s 峰值 RMS」，只要那一下落在前向窗里就算「还在段内」，
  坐标因此停在**起声之前的静音**里（2026-10-12 21:30 实测早 0.39 s）；归位改用 `AttackWindowSeconds`=0.05 s
  短窗 + 同一个门限，向后再走到真的进声处（命中说明里显示「已归位到起声（+X.XXs）」）。
- **双窗口复核**：插件同时搜「开窗」（中心 = 标称边界 − 当前偏移）与「表窗」（中心 = 课表标称边界），
  再按峰值 dB 复核：一致 → 用开窗；**任何一侧强出 >6 dB → 用那一侧**（开窗更强 = 铃确实远离边界，
  表窗更强 = 开窗被偏移锚到杂音上；v1.0.5 补对称）；两窗峰值差 ≤2 dB → 判为同一段长铃的
  先后两击、取更早的开窗；差距落在 2~6 dB 中间带 → 判冲突（不写偏移、只落一条默认不参与的旁证样本）。

v1.1.0 的两条补充：

- **模板锚点**：模板匹配从「闸门未命中才跑的兜底」提升为**每窗先跑**的一步，命中就把两个闸门窗口都收窄到
  「模板命中位置 ± `OnsetGate.AnchorApertureSeconds`(3 s)」，起声仍由「回溯到长铃起点 + 归位」定位；
  未命中则完全按老行为（窗口中心 ±8 s）。原因：闸门的「比值竞赛」在吵闹窗口里会被窗内瞬态抢走
  （2026-10-14 09:40 选中 100×、10:10 选中 188×，都落在人声/桌椅里），而模板回答的是「这段波形就是我们的铃」。
  实测 75 个历史窗口命中 28 个（37%）：其中 20 个与老行为一致（≤0.05 s），8 个被改动，
  7 个改动量 >6 s 且都是老行为落在边界另一侧瞬态上的窗口。命中率只有三成多，所以它只当锚点、不当唯一判据。
  注意模板对齐点落在**铃段内部**（实测比可听第一击晚 0.7~1.6 s），这也是起声必须靠回溯+归位、而不是直接用模板坐标的原因。
- **大偏移自适应**：用户实测「修正所需偏移可能超过 20 s」。布防提前量取 `clamp(max(配置值, |当前偏移|+10), 配置值, 60)`（`CalibrationScheduler.CurrentLead`），
  模板搜索半窗取 `max(配置值, |当前偏移|+8)`（`CalibrationRunner`），两者同公式，音频一定覆盖得到扫描区间；
  偏移小时与本项无关、行为与旧版完全一致。

## 用你自己的录音标定

1. `TemplateTool scan <你的录音.wav>` —— 确认事件定位是否符合预期（起止秒数、峰值 dB）；
2. `TemplateTool extract <录音.wav> <模板.wav> <起始秒-结束秒>` 截出模板；
3. `TemplateTool selftest <模板.wav> <同一录音.wav> 0.6 0.45 15` —— 同源应接近 **1.000**；
4. 再拿一段**不含铃声**的录音当负样本，确认 `selftest` 的最佳 NCC 明显低于阈值；
5. 若需要，按第 3、4 步量到的值在设置页调整 `MatchNccMin` / `MatchSpectralMin`（改完立即生效，无需重启）。

## ReplayTool

对已采集的边界音频（`DebugDumpAudio` 转存的 `Dumps/*.wav`）重跑一遍**与插件完全相同**的判定链，
用于离线复核「这个边界插件会选到哪一点、为什么」。复用生产代码（`OnsetGate`、`TemplateMatcher`、
`RingDetector`、`RingCandidateSelector`、`CaptureAudio` 直接链接编译）。

注意：设置页的「清除无用录音」只清 7 天以前、且**不在本工具断言夹具名单**（`DumpCleaner.ProtectedFiles`）里的 `Dumps/*.wav`；下面这些用例点名的录音是永久保留的，不会被它删掉。

```
ReplayTool <dump.wav> <模板目录> <边界在dump内秒数> [内核偏移秒=-5.1] [搜索半窗秒=12]
ReplayTool fitter <样本序列文件> [死区秒=0.3]
ReplayTool gate-reconcile <dump.wav> [当时偏移秒]       # 只跑双窗口闸门 + 复核，打印结论
ReplayTool gate-reconcile-test <Dumps 目录>             # 逐条断言 12 个真实窗口的复核结论
ReplayTool gate-scan <dump.wav|目录> [偏移秒]           # 批量扫起响沿命中（含靠「高声压起响」入选的标记）
ReplayTool gate-guard <Dumps 目录>                      # 基线静默排除断言：任何命中都不得依赖「除以数字静默」
ReplayTool absolute-required-test                       # 未观测到切换时的绝对口径 4 条断言
ReplayTool estimate-test                                # 写入限幅/步进 + 估计器（离群、重开段、趋势门槛）22 条断言
ReplayTool manual-fit <offset-samples.jsonl> [日期]     # 跑一遍手动拟合：当天有效样本 → 要写入的偏移
ReplayTool sample-manage-test                           # 样本管理 / 判据位置 22 条断言
ReplayTool dumps-clear-test                             # 「清除无用录音」的删除/保留判据 20 条断言（近期 / 断言夹具 / 非 wav / 子目录一律不动）
ReplayTool notify-test                                  # 人工审核提醒的开关/阈值判定 7 条
ReplayTool envelope <dump.wav> [步长秒]                 # 逐格最大 dBFS 包络（核对起响位置与长铃段）
```

- 第一条命令打印：**模板匹配结果 → 老行为闸门（边界 ±8s）与 v1.1.0 锚定闸门（模板 ±3s）各一行** → 本窗口「有无可信测量」的结论。
  v1.1.0 起模板先跑、命中即定锚，因此这两行就是「同一个窗口在新旧两条路径下各选到哪一点」的对照；
  读历史窗口时以锚定那行为准（模板未命中时该行不出现，生产里就等价于老行为）；
- **重放历史窗口必须传「该窗口布防时冻结的偏移」**（`ActiveWindow.KernelOffsetSeconds`），不能用之后的实时偏移 ——
  两个搜索窗口的中心都由它决定，传错会让结论完全失真；
  `gate-reconcile` 不传偏移时按文件名（只精确到秒）反推，会有约 1 s 的系统偏差，只看结论别看绝对值；
- `fitter` 子命令用于**离线验证偏移估计算法**：样本序列文件每行 `yyyy-MM-dd HH:mm:ss,所需偏移秒`，
  工具会逐步喂给生产类 `DriftFitter` 并打印每一步的估计值与是否写入，
  可在不接触运行中的 ClassIsland 的前提下对比不同估计策略的稳定性。
